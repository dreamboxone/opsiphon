# Opsiphon — سایفون برای OpenWrt (با رابط گرافیکی LuCI)

**نسخه ۱.۰.۴** · پشتیبانی و تماس: [t.me/routekernel1](https://t.me/routekernel1)
🇬🇧 **[English guide: README.md](README.md)**

Opsiphon کلاینت کنسولی متن‌باز
[psiphon-tunnel-core](https://github.com/Psiphon-Labs/psiphon-tunnel-core)
را به‌صورت یک سرویس واقعی OpenWrt اجرا می‌کند و یک صفحه LuCI هم برایش دارد،
یعنی تونل را به‌جای خط فرمان از رابط وب روتر روشن می‌کنی، وضعیتش را می‌بینی و
تنظیمش می‌کنی.

روی **OpenWrt 25.12** توسعه داده شده، تارگت `ipq40xx/chromium` و معماری
`arm_cortex-a7_neon-vfpv4`. ریلیزها بستهٔ `.ipk` برای **۲۴.۱۰ و ۲۳.۰۵** را هم
دارند و چهار معماری را پوشش می‌دهند؛ اسکریپت‌های بیلد بیشتر از این را.

---

## ۱) نصب

چون OpenWrt در نسخه ۲۵.۱۲ مدیر بسته را عوض کرد، هر ریلیز **هر دو فرمت** را
دارد. جفتی را بردار که با روتر تو می‌خواند:

| نسخه OpenWrt تو | مدیر بسته | این دو فایل را بگیر |
|---|---|---|
| ۲۵.۱۲ و بالاتر | `apk` | `opsiphon-<version>.<arch>.apk` و `luci-app-opsiphon-<version>.apk` |
| ۲۴.۱۰ و ۲۳.۰۵ | `opkg` | `opsiphon_<version>_<arch>.ipk` و `luci-app-opsiphon_<version>_all.ipk` |

معماری روتر همان `DISTRIB_ARCH` در فایل `/etc/openwrt_release` است (روی ۲۳.۰۵
و ۲۴.۱۰ دستور `opkg print-architecture` هم همان را چاپ می‌کند). بسته
`luci-app-opsiphon` مستقل از معماری است — یک فایل روی همه روترها کار می‌کند.

**روی OpenWrt ۲۵.۱۲ و بالاتر:**

```sh
scp opsiphon-*.apk luci-app-opsiphon-*.apk root@192.168.1.1:/tmp/
ssh root@192.168.1.1 'apk add --allow-untrusted /tmp/opsiphon-*.apk /tmp/luci-app-opsiphon-*.apk'
```

**روی OpenWrt ۲۴.۱۰ و ۲۳.۰۵:**

```sh
scp opsiphon_*.ipk luci-app-opsiphon_*.ipk root@192.168.1.1:/tmp/
ssh root@192.168.1.1 'opkg update && opkg install /tmp/opsiphon_*.ipk /tmp/luci-app-opsiphon_*.ipk'
```

بعد در LuCI برو به **Services → Psiphon**.

بلافاصله بعد از نصب هیچ چیزی اجرا نمی‌شود: تونل خاموش می‌ماند تا خودت یک‌بار
دکمه **Connect** را بزنی. این عمدی است — تصمیم با توست که روتر از چه لحظه‌ای
ترافیک را تونل کند.

پیش‌نیازها (`jshn`، `libubox`، `luci-base`) بخشی از نصب معمولی OpenWrt + LuCI
هستند، پس برای نصب نیازی به اینترنت نیست.

نصب بدون پکیج، روی هر نسخه‌ای:

```sh
./install-manual.sh root@192.168.1.1 arm_cortex-a7_neon-vfpv4
```

### حذف برنامه (Uninstall)

```sh
ssh root@192.168.1.1
/usr/libexec/opsiphon-passwall remove     # فقط اگر اجازه داده بودی به PassWall2 دست بزند
/etc/init.d/opsiphon stop
apk del luci-app-opsiphon opsiphon        # روی ۲۴.۱۰ و قدیمی‌تر: opkg remove ...
```

این کار سرویس، هسته و صفحه‌ی وب را برمی‌دارد. حذف پکیج‌ها عمداً تنظیمات تو را
نگه می‌دارد تا اگر دوباره نصب کردی از همان‌جا ادامه بدهی. اگر آن‌ها را هم
می‌خواهی پاک کنی:

```sh
rm -rf /etc/config/opsiphon /etc/opsiphon
```

در `/etc/opsiphon` دیتابیس سایفون، تاریخچه‌ی مصرف (`usage.csv`) و نسخه‌های
پشتیبان کانفیگ PassWall2 نگهداری می‌شود، پس فقط وقتی پاکش کن که واقعاً بخواهی
همه‌چیز از صفر شود. وضعیت موقت هم در `/var/run/opsiphon` و `/var/log/opsiphon`
است که با ریبوت خودش می‌رود.

دو چیز عمداً دست‌نخورده می‌ماند، چون مال نرم‌افزار دیگری است: فایل‌های
`geoip.dat` و `geosite.dat` در `/usr/share/v2ray`، و هر تنظیم دیگر PassWall2
غیر از نود — یعنی اگر دکمه‌ی *Keep Iran traffic direct* را زده باشی، آن قانون
همان‌طور که تنظیم شده باقی می‌ماند. در `/etc/opsiphon/backup` هم از قبلِ هر
تغییر، یک نسخه‌ی زمان‌دار از `/etc/config/passwall2` هست که اگر خواستی برگردی.

## ۲) صفحه LuCI

### پنل وضعیت

| فیلد | یعنی چه |
| --- | --- |
| **Connection** | `Stopped` سرویس خاموش · `Connecting…` روشن ولی هنوز تونل ندارد · `Connected` تونل برقرار است |
| **Country** | کشوری که ترافیک از آن‌جا از شبکه Psiphon خارج می‌شود — یعنی سایت‌ها فکر می‌کنند تو آن‌جایی |
| **Detected client country** | کشوری که Psiphon فکر می‌کند *تو* در آن هستی |
| **Connected for** | مدت زمانی که تونل فعلی برقرار بوده |
| **Traffic (down / up)** | حجم دریافتی / ارسالی از داخل تونل از زمان روشن شدن |
| **Local proxies** | آدرس پروکسی‌های SOCKS5 و HTTP که تونل در اختیار می‌گذارد |
| **Start on boot** | اینکه بعد از ریستارت روتر دوباره وصل شود یا نه |
| **Status** | «وصل شد»، «در حال اتصال»، یا وقتی چیزی هست که باید بدانی همان پیام |

پنل هر ۳ ثانیه به‌روز می‌شود.

### دکمه‌ها

| دکمه | چه می‌کند |
| --- | --- |
| **Connect** | مقدار `enabled=1` را ست می‌کند و سرویس را استارت می‌کند. تنها کلیدی که تونل را روشن می‌کند همین است. |
| **Disconnect** | `enabled=0` و توقف سرویس. |
| **Reconnect** | ری‌استارت سرویس — بعد از تغییر تنظیمات، یا برای گرفتن سرور دیگر. |
| **Logs** | لاگ پیام‌های اخیر سایفون (جدیدترین بالا) — برای عیب‌یابی. |

### تب General

| گزینه | چه می‌کند |
| --- | --- |
| **Start on boot** | بعد از ریبوت روتر خودکار دوباره وصل می‌شود. فقط وقتی معنی دارد که حداقل یک‌بار Connect زده باشی. |
| **Country** | کشور خروجی را مجبور می‌کند. حالت `Auto` (پیش‌فرض) یعنی خود سایفون سریع‌ترین سرور را انتخاب کند — تا وقتی کشور خاصی لازم نداری روی Auto بگذار. لیست کشورها از همان چیزی پر می‌شود که سایفون واقعاً موجود اعلام کرده. |
| **SOCKS5 port** | پورت پروکسی محلی SOCKS5 (پیش‌فرض `1080`). مقدار `0` یعنی غیرفعال. |
| **HTTP proxy port** | پورت پروکسی محلی HTTP (پیش‌فرض `8080`). مقدار `0` یعنی غیرفعال. |
| **Listen interface** | خالی یعنی پروکسی‌ها فقط از خود روتر در دسترس‌اند (`127.0.0.1`). اگر `br-lan` بگذاری، دستگاه‌های شبکه هم می‌توانند با `<آی‌پی روتر>:1080` استفاده کنند. |
| **Collect traffic statistics** | شمارنده‌های حجم مصرف را روشن می‌کند. اگر خاموشش کنی سایفون کمی کم‌حرف‌تر می‌شود. |

### تب Advanced

| گزینه | چه می‌کند |
| --- | --- |
| **Data directory** | جایی که سایفون لیست سرورها و دیتابیس داخلی‌اش را نگه می‌دارد. پیش‌فرض `/etc/opsiphon/data` است (بعد از ریبوت باقی می‌ماند). اگر فلش روتر برایت مهم است، روی حافظه USB بگذار، مثلاً `/mnt/sda1/opsiphon`. |
| **Establish timeout (s)** | اگر بعد از N ثانیه تونل برقرار نشد، از نو شروع کن. `0` یعنی مقدار پیش‌فرض خود سایفون. |
| **Upstream proxy** | تونل را اول از داخل یک پروکسی دیگر رد می‌کند، مثلاً `socks5://127.0.0.1:10808` یا `http://127.0.0.1:8118`. این راه فرار برای شبکه‌ای است که سایفون حتی به سرورهای خودش هم نمی‌رسد ولی یک پروکسی دیگر روی روتر هنوز کار می‌کند. |
| **Embedded server list file** | مسیر فایلی که در آن لیست سرورهای سایفون هست (مثلاً `/etc/opsiphon/server_list`). با آن، تونل بدون دانلود لیست سرور از اینترنت هم می‌تواند شروع کند — همان دانلودی که معمولاً اول از همه بسته می‌شود. |
| **Diagnostic notices** | اجازه می‌دهد سایفون هشدارها، خطاها و تعداد سرورهای کاندید را گزارش کند. روشن نگهش دار: توضیحی که هنگام وصل‌نشدن در پنل وضعیت می‌بینی از همین می‌آید. |
| **Limit tunnel protocols** | محدود کردن پروتکل‌های مبهم‌سازی (`OSSH`، `QUIC-OSSH`، `FRONTED-MEEK-OSSH` و…). همه را تیک‌نخورده بگذار — سایفون خودش طوری طراحی شده که هرکدام رد می‌شود را انتخاب کند. فقط برای تست اینکه کدام پروتکل از فیلتر عبور می‌کند به درد می‌خورد. |
| **Psiphon network** — *Sponsor ID*، *Propagation channel ID*، *Remote server list URL*، *Signature key* | این‌ها هویت کلاینت را به شبکه Psiphon معرفی می‌کنند. Sponsor ID و Propagation ID تعیین می‌کنند این کلاینت چه مجموعه سروری و چه صفحه خانگی‌ای بگیرد؛ آدرس لیست سرور جایی است که کلاینت لیست سرورها را از آن می‌گیرد و کلید امضا ثابت می‌کند آن لیست جعلی نیست. مقادیر پیش‌فرض همان **مقادیر عمومی متن‌باز** منتشرشده با psiphon-tunnel-core هستند. فقط در صورتی عوضشان کن که Psiphon Inc. کانفیگ اختصاصی به تو داده باشد. |

## ۳) بعد از اتصال، چطور از تونل استفاده کنیم؟

سایفون یک تونل با دو پروکسی محلی می‌سازد. فرستادن ترافیک به داخل آن یک تصمیم
جداگانه است:

**فقط یک دستگاه یا یک مرورگر:** در تب General گزینه *Listen interface* را
`br-lan` بگذار، بعد *Reconnect* بزن و در دستگاه مقصد تنظیم کن:

* SOCKS5 → `<آی‌پی روتر>:1080`
* HTTP → `<آی‌پی روتر>:8080`

**کل شبکه:** از یک مدیر پروکسی که می‌تواند همه ترافیک را ریدایرکت کند استفاده
کن، مثل PassWall2 یا OpenClash، و پروکسی سایفون را به‌عنوان upstream بهش بده:
یک نود از نوع `Socks5` با سرور `127.0.0.1` و پورت `1080` بساز و فعالش کن. از آن
به بعد خودِ آن برنامه ریدایرکت شفاف، DNS و قوانین بای‌پس (مثلاً بیرون نگه داشتن
سایت‌های داخلی از تونل) را انجام می‌دهد.

## ۴) وقتی وصل نمی‌شود (فیلترینگ شدید)

سایفون خودش هیچ‌وقت تسلیم نمی‌شود: بی‌نهایت سرورها و پروتکل‌ها را عوض می‌کند و
دوباره تلاش می‌کند. برای همین وضعیت روی **Connecting…** می‌ماند (نشان بعد از دو
دقیقه قرمز می‌شود) و کنارش می‌نویسد چند وقت است تلاش می‌کند و چند بار. بعد از ۴۵
ثانیه یک جعبه توضیح ظاهر می‌شود که دلیل واقعی را می‌گوید، در یکی از دو حالت:

**«هنوز هیچ سروری برای تلاش ندارد»** — یعنی تعداد سرورهای کاندید صفر است:
سایفون اصلاً نتوانسته لیست سرورهایش را دانلود کند، پس چیزی برای وصل شدن ندارد.
این لیست بار اول از اینترنت گرفته می‌شود و معمولاً همان اولین چیزی است که فیلتر
می‌شود. کارهایی که جعبه پیشنهاد می‌دهد، به‌ترتیب:

۱. در تب Advanced گزینه **Upstream proxy** را روی پروکسی‌ای بگذار که همین حالا
   روی روتر کار می‌کند، مثلاً `socks5://127.0.0.1:10808` از یک کلاینت
   V2Ray/Xray که بالا است. سایفون از داخل همان بوت‌استرپ می‌کند و بعد از اینکه
   لیست سرورها را گرفت معمولاً روی پای خودش می‌ایستد.

۲. یا **Embedded server list file** را به فایلی بده که لیست سرورها را از یک
   نصب سالم سایفون در آن کپی کرده‌ای؛ آن‌وقت اصلاً نیازی به دانلود نیست.

۳. اگر خود روتر اصلاً اینترنت ندارد، اول آن را درست کن (Network → Interfaces).

**«سرور دارد ولی هنوز تونل نساخته»** — یعنی سرورها را دارد و مدام سرور و
پروتکل‌های مبهم‌سازی مختلف را امتحان می‌کند؛ زیر فیلترینگ سنگین این کار ممکن است
چند دقیقه طول بکشد. *Limit tunnel protocols* را خالی بگذار، *Country* را
اگر دستی ست کرده‌ای به Auto برگردان، و با **Logs** ببین هر تلاش چه
گزارشی می‌دهد.

در هر دو حالت آخرین هشدار یا خطای سایفون زیر **Last message** نشان داده می‌شود
(کوتاه‌شده تا فقط بخش مهمش بماند) و تاریخچه کامل در **Logs** یا با
دستور `opsiphon-stat -l` از طریق SSH در دسترس است.

## ۵) وقتی خودِ لیست سرورها فیلتر است (بوت‌استرپ)

یک کلاینت تازه‌نصب سایفون هیچ سروری نمی‌شناسد. سرورها را با دانلود یک فایل
لیست امضاشده از `s3.amazonaws.com` یاد می‌گیرد، و در شبکه‌ی به‌شدت فیلترشده
معمولاً همین دانلود اولین چیزی است که می‌شکند — نتیجه‌اش تونلی است که تا ابد
روی *Connecting…* می‌ماند و صفر سرور کاندید دارد.

راه‌حل Opsiphon **آینه‌های بوت‌استرپ** است. گزینه‌ی *Bootstrap mirrors* (تب
Advanced، در UCI: `server_list_urls`) هر تعداد آدرس برای همان فایل می‌گیرد؛
سایفون همه را کاندید می‌داند و آدرس بسته‌شده عملاً کنار می‌رود.

این کار ذاتاً امن است و بهتر است دلیلش را بدانی: آن لیست **با کلید RSA توسط
سایفون امضا شده** و کلاینت امضا را با `RemoteServerListSignaturePublicKey` که
در کانفیگ خودش دارد بررسی می‌کند. پس یک آینه نمی‌تواند لیست جعلی بدهد یا
دستکاری‌اش کند؛ بدترین کاری که یک آینه‌ی قدیمی می‌کند این است که نسخه‌ی
قدیمی‌تر بدهد.

### خودِ ریپازیتوری، آینه است

فایل `.github/workflows/mirror-bootstrap.yml` روی سرورهای خود گیت‌هاب اجرا
می‌شود — که به آدرس اصلی دسترسی دارند — روزی چهار بار لیست سرورها را دانلود
می‌کند و در `mirror/server_list_compressed` کامیت می‌کند. کانفیگ پیش‌فرض هم از
قبل به همان اشاره می‌کند:

```
list server_list_urls 'https://raw.githubusercontent.com/dreamboxone/opsiphon/master/mirror/server_list_compressed'
list server_list_urls 'https://s3.amazonaws.com/psiphon/web/mjr4-p23r-puwl/server_list_compressed'
```

یعنی `raw.githubusercontent.com` — که در خیلی از شبکه‌هایی که AWS بسته است هنوز
باز است — می‌شود راه ورود. کافی است یک‌بار در ریپازیتوری Actions را فعال کنی
(تب Actions → فعال‌سازی، و بعد یک‌بار دستی *Mirror Psiphon bootstrap list* را
اجرا کن تا اولین نسخه ساخته شود).

اگر هیچ‌کدام از این دو آدرس هم از روتر تو در دسترس نبود، همان دو راه فرار بخش
قبل سر جایش است: **Upstream proxy** یا **Embedded server list file**.

### انتشار نسخه‌ها هم خودکار است

فایل `.github/workflows/release.yml` هسته‌ی سایفون را با Go برای چهار معماری
(`arm_cortex-a7_neon-vfpv4`، `aarch64_cortex-a53`، `mipsel_24kc`، `x86_64`) از
سورس می‌سازد، هر معماری را دو بار بسته‌بندی می‌کند — `.apk` با ابزار apk از
SDK رسمی OpenWrt و `.ipk` با `build-ipk.sh` — بررسی می‌کند که هر دو فرمت واقعاً
دقیقاً یک درخت فایل با هستهٔ اجراپذیر دارند، و همه را به‌صورت GitHub Release
منتشر می‌کند:

```sh
git push -u origin master        # بار اول
git tag v1.0.2 && git push origin v1.0.2
```

## ۶) PassWall2، آمار مصرف و قوانین ایران

### پنل PassWall2

Opsiphon خودش تشخیص می‌دهد PassWall2 نصب است یا نه و وضعیت اتصالشان را نشان
می‌دهد. تا وقتی گزینه‌ی *Keep a PassWall2 node in sync* (تب General) روشن است،
با هر بار روشن شدن تونل یک نود در PassWall2 ساخته یا به‌روز می‌شود:

```
config nodes 'opsiphon'
	option remarks 'Opsiphon (Psiphon)'
	option type 'Xray'
	option protocol 'socks'
	option address '127.0.0.1'
	option port '1080'      # با پورت SOCKS5 خودت هماهنگ می‌شود
```

این نود **هیچ‌وقت خودبه‌خود فعال نمی‌شود** — عبور دادن کل ترافیک تصمیم توست.
دکمه‌های پنل:

| دکمه | کارش چیست |
| --- | --- |
| **Create / refresh node** | نود بالا را می‌سازد/به‌روز می‌کند، هماهنگ با پورت فعلی SOCKS. |
| **Use as active node** | اگر PassWall2 نود shunt داشته باشد، `default_node` آن را روی Opsiphon می‌گذارد (قوانین خودت دست‌نخورده می‌ماند)؛ وگرنه آن را نود اصلی می‌کند. ضمناً `localhost_proxy` را خاموش می‌کند — پایین‌تر توضیح داده شده. |
| **Keep Iran traffic direct** | قانون `Iran` (شامل `geosite:ir` و `geoip:ir`) را روی `_direct` می‌گذارد تا سایت‌ها و آی‌پی‌های ایرانی از تونل رد نشوند، و آدرس فایل‌های geo را هم به نسخه ایرانی تغییر می‌دهد. |
| **Send Iran traffic through tunnel** | همان قانون را به `_default` برمی‌گرداند. |
| **Remove node** | نود را حذف می‌کند و اگر فعال بوده جدایش می‌کند. |

قبل از هر تغییر، از `/etc/config/passwall2` یک نسخه پشتیبان زمان‌دار در
`/etc/opsiphon/backup` ساخته می‌شود (۱۰ نسخه آخر نگه داشته می‌شود).

**چرا *Use as active node* گزینهٔ `localhost_proxy` را خاموش می‌کند.** آن تنظیم
ترافیک خروجی خودِ روتر — و DNS خودِ روتر — را از نود فعال رد می‌کند. نود فعال حالا
یک پروکسی SOCKS است که خودِ سایفون روی `127.0.0.1` سرو می‌کند، پس اتصال‌های خودِ
سایفون به شبکهٔ Psiphon به پروکسی خودش برمی‌گردد — پروکسی‌ای که تا وقتی تونل ساخته
نشده چیزی برای جواب دادن ندارد. نتیجه این است که تونل هیچ‌وقت وصل نمی‌شود و تنها
نشانه‌اش سیل هشدارهای `SOCKS proxy accept error` است. کلاینت‌های LAN تو تحت تأثیر
قرار نمی‌گیرند — آن‌ها را `client_proxy` پوشش می‌دهد. دکمهٔ **Remove node** مقدار
قبلی `localhost_proxy` را برمی‌گرداند.

### قوانین مسیریابی ایران

پنل، دو فایل داده‌ی [Iran-v2ray-rules](https://github.com/chocolate4u/Iran-v2ray-rules)
را دانلود می‌کند و حجم و تاریخشان را نشان می‌دهد:

* `geoip.dat` — شامل `geoip:ir`
* `geosite.dat` — شامل `geosite:ir`

فایل‌ها در پوشه‌ی asset خود PassWall2 (`v2ray_location_asset`، معمولاً
`/usr/share/v2ray/`) نوشته می‌شوند، و اگر `/usr/share/xray` یا
`/usr/share/sing-box` وجود داشته باشد همان‌جا هم کپی می‌شوند؛ بعدش PassWall2
ری‌استارت می‌شود. اگر دانلود ناقص باشد، فایل سالم قبلی جایگزین نمی‌شود. هر وقت
خواستی همان دکمه را دوباره بزن تا به‌روز شوند.

یک نکته مهم: این فایل‌ها **داده‌ی مسیریابی Xray / sing-box** هستند. خود سایفون
هیچ قانون مسیریابی ندارد — یک تونل است، نه روتر — پس «ایران از تونل رد نشود» را
عملاً مدیر پروکسی انجام می‌دهد، و به همین دلیل این بخش کنار پنل PassWall2 معنی
پیدا می‌کند.

### آمار مصرف

شمارنده‌های تونل، روزانه در فایل `<data directory>/usage.csv` جمع می‌شوند (یک
خط برای هر روز، هر ۵ دقیقه و موقع توقف نوشته می‌شود، پس تقریباً هیچ فشاری روی
فلش نیست). پنل Traffic نشان می‌دهد:

* نمودار دایره‌ای دانلود در برابر آپلود برای بازه‌ی انتخابی،
* مجموع امروز / ۷ روز / ۳۰ روز / کل،
* نمودار ستونی ۱۴ روز اخیر.

مرز روز، تاریخ و تایم‌زون خود روتر است. دستور `opsiphon-usage report` همین
اعداد را به‌صورت JSON می‌دهد و `opsiphon-usage reset` تاریخچه را پاک می‌کند.

## ۸) بیلد کردن

### هسته سایفون

نیازمند Go 1.26+ و git. چون CGO خاموش است، خروجی یک باینری استاتیک است که
بدون تغییر روی OpenWrt (musl) اجرا می‌شود.

```sh
./build/build-core.sh armv7      # ipq40xx / Cortex-A7 (پیش‌فرض)
./build/build-core.sh aarch64    # Filogic، Rockchip و…
./build/build-core.sh mipsel     # ramips / mt7621
./build/build-core.sh x86_64
```

خروجی: `prebuilt/<معماری>/psiphon-tunnel-core`.

### پکیج‌ها

برای OpenWrt ۲۵.۱۲ و بالاتر (`.apk`):

```sh
./build/build-apk.sh arm_cortex-a7_neon-vfpv4 \
    ~/openwrt-sdk-25.12.5-*/staging_dir/host/bin/apk
```

برای ۲۴.۱۰ و ۲۳.۰۵ (`.ipk`) — بدون نیاز به SDK و بدون ابزار apk:

```sh
./build/build-ipk.sh arm_cortex-a7_neon-vfpv4
```

`build-apk.sh` دقیقاً همان مراحلی را انجام می‌دهد که `include/package-pack.mk`
برای APK انجام می‌دهد (لیست فایل‌ها، conffiles با sha256، اسکریپت‌های نصب و
حذف) و بعد `apk mkpkg` را صدا می‌زند. `build-ipk.sh` معادل همان کار را برای
opkg می‌کند و همان تاربال `debian-binary` + `data.tar.gz` + `control.tar.gz`
را می‌سازد که `scripts/ipkg-build` در سورس OpenWrt می‌سازد. در هیچ‌کدام چیزی
کامپایل نمی‌شود؛ مسیر apk فقط به ابزار `apk` از هر SDK نسخه ۲۵.۱۲ نیاز دارد و
مسیر ipk به هیچ چیز جز tar و gzip — که کاربردی است، چون سیستم build کامل
OpenWrt روی فایل‌سیستم غیرحساس‌به‌حروف (مثل درایو ویندوز) اجرا نمی‌شود. هر دو
را با کاربر root اجرا کن تا مالکیت فایل‌های داخل پکیج `root:root` شود.

هر دو لیست فایل‌هایشان را از `build/packages.inc.sh` می‌خوانند، پس دو فرمت
هیچ‌وقت از هم دور نمی‌افتند؛ CI در هر بیلد این را ثابت می‌کند: درخت فایل را از
دل هر دو پکیج بیرون می‌کشد و با هم diff می‌گیرد.

روی یک ماشین لینوکسی واقعی، مسیر SDK کامل هم کار می‌کند:

```sh
./build/build-package.sh ~/openwrt-sdk-25.12.5-<target> arm_cortex-a7_neon-vfpv4
```

## ۹) معماری داخلی

```
psiphon-tunnel-core  --stderr-->  opsiphon-notices (awk)  -->  /var/run/opsiphon/state
        ^                                                              |
        |                                                              v
/var/etc/opsiphon.json  <-- opsiphon-mkconfig <-- UCI      rpcd: luci.opsiphon  -->  LuCI
```

* `opsiphon-mkconfig` در هر بار استارت، کانفیگ JSON سایفون را از روی UCI می‌سازد.
* `opsiphon-notices` جریان پیام‌های سایفون را می‌خواند و وضعیت زنده و یک لاگ
  محدود (حداکثر ۴۰۰ خط) را در RAM نگه می‌دارد — هیچ چیزی روی فلش نوشته نمی‌شود.
* `luci.opsiphon` همان بک‌اند rpcd/ubus است که صفحه LuCI از آن وضعیت می‌گیرد و
  فرمان‌ها را به آن می‌دهد.
